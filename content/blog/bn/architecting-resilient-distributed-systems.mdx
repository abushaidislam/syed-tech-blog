স্কেলেবল সফটওয়্যার তৈরি করা চ্যালেঞ্জিং, তবে একটি ডিস্ট্রিবিউটেড ক্লাস্টারে অপ্রত্যাশিত ব্যর্থতা সত্ত্বেও টিকে থাকতে পারে এমন সফটওয়্যার তৈরি করা সম্পূর্ণ ভিন্ন দক্ষতার বিষয়। সিঙ্গল-প্রসেস মনোলিথিক অ্যাপ্লিকেশনগুলোতে ব্যর্থতা বাইনারি: হয় প্রসেসটি চলছে, না হয় এটি ক্র্যাশ করেছে। আপনি একটি কোর ডাম্প বা স্ট্যাক ট্রেস পরীক্ষা করেন, সার্ভিসটি রিস্টার্ট করেন এবং অনিয়মটি তদন্ত করেন।

ডিস্ট্রিবিউটেড সিস্টেমে ব্যর্থতা কখনোই বাইনারি নয়। এটি সূক্ষ্ম, আংশিক এবং ধারাবাহিক। যেকোনো নির্দিষ্ট মুহূর্তে শত শত নোডের মধ্যে হার্ড ড্রাইভের কর্মক্ষমতা হ্রাস পেতে পারে, নেটওয়ার্ক রাউটার প্যাকেট ড্রপ করতে পারে, গার্বেজ কালেকশন পজের কারণে ল্যাটেন্সি লাফিয়ে বাড়তে পারে এবং ডাউনস্ট্রিম ডিপেন্ডেন্সিগুলোর গতি থমকে যেতে পারে। একটি সিস্টেম যা ধরে নেয় যে নেটওয়ার্ক বাউন্ডারি সর্বদা নির্ভরযোগ্য, তা প্রোডাকশন কোডের প্রথম লাইন লেখার আগেই মূলগতভাবে ত্রুটিপূর্ণ।

প্রকৃত রেজিলিয়েন্স অর্জনের জন্য ক্রমাগত ব্যর্থতা ঘটবে—এই সত্যটিকে মেনে নেওয়া প্রয়োজন। প্রতিটি সম্ভাব্য ফেইলর মোড প্রতিরোধ করার চেষ্টা করার চেয়ে, উচ্চ-কার্যক্ষমতাসম্পন্ন ইঞ্জিনিয়ারিং টিমগুলো এমন টপোলজি ডিজাইন করে যা শক শোষণ করে, ক্যাটাস্ট্রফিক ক্যাসকেড আইসোলেট করে এবং গ্রেসফুলি পারফর্ম্যান্স ডিগ্রেড করে।

Resilience is not the total absence of operational failure. Resilience is the architectural capacity of a distributed topology to absorb localized degradation without collapsing the wider human and mechanical workflow.

## নির্ভরযোগ্য নেটওয়ার্কের বিভ্রম: ফ্যাল্যাসিগুলোর পুনঃপর্যালোচনা

১৯৯৪ সালে, সান মাইক্রোসিস্টেমসের এল. পিটার ডয়েচ এবং অন্যান্য অগ্রগামী প্রকৌশলীরা *Fallacies of Distributed Computing* বা ডিস্ট্রিবিউটেড কম্পিউটিংয়ের ভুল ধারণাগুলো প্রণয়ন করেছিলেন। তিন দশক পরেও, আধুনিক ক্লাউড ইঞ্জিনিয়ারিং টিমগুলো ঠিক একই ধরনের আর্কিটেকচারাল ভুল করে চলেছে, যা প্রায়শই কিউবারনেটিস অ্যাবস্ট্রাকশন, সার্ভিস মেশ এবং ম্যানেজড ক্লাউড প্রিমিটিভসের স্তরের নিচে ঢাকা পড়ে যায়।

মাইক্রোসার্ভিস ডিজাইনকারী প্রতিটি ইঞ্জিনিয়ারের এই মৌলিক সত্যগুলো আত্মস্থ করা আবশ্যক:

1. **নেটওয়ার্ক নির্ভরযোগ্য:** প্যাকেট ড্রপ হয়, সুইচগুলো তাদের ফরওয়ার্ডিং টেবিল রিসেট করে এবং আটলান্টিক মহাসাগরের তলদেশের তার ক্ষতিগ্রস্ত হয়।
2. **ল্যাটেন্সি শূন্য:** প্রতিটি বাউন্ডারি অতিক্রম করার সময় সিরালাইজেশন, কার্নেল কনটেক্সট সুইচ, ফিজিক্যাল ট্রানজিট এবং ডিসিরালাইজেশন ওভারহেড যুক্ত হয়।
3. **ব্যান্ডউইথ অসীম:** বিশাল ডেটা ব্যাকফিলের সময় ইন্ট্রা-ডাটা সেন্টার লিঙ্কগুলো স্যাচুরেটেড হলে তা সংলগ্ন ট্রানজেকশনাল ওয়ার্কলোডের গতি কমিয়ে দেয়।
4. **টপোলজি কখনোই পরিবর্তিত হয় না:** ক্লাউড প্রোভাইডাররা ভার্চুয়াল হাইপারভাইজার মাইগ্রেট করে, স্পট ইনস্ট্যান্সগুলো দুই মিনিটের সতর্কবার্তায় বন্ধ হয়ে যায় এবং অটোস্কেলাররা ক্রমাগত এন্ডপয়েন্ট পরিবর্তন করে।

**Failure Mode Warning:** আপনার মাইক্রোসার্ভিস যদি একই মেমোরির মেথড ইনভোকেশনের মতো একই কন্টেইনারের অন্য একটি RPC কলকে ট্রিট করে, তবে আপনি একটি ভঙ্গুর ডিস্ট্রিবিউটেড মনোলিথ তৈরি করছেন। একটি স্থবির বা আটকে যাওয়া নেটওয়ার্ক সকেট শেষ পর্যন্ত আপনার ওয়েব সার্ভারের কানেকশন থ্রেড পুল শেষ করে দেবে।

নেটওয়ার্ক প্যাকেট লসের কারণে যখন কোনো অভ্যন্তরীণ HTTP রিকোয়েস্ট আটকে যায়, তখন ক্লায়েন্ট অ্যাপ্লিকেশনটি সাধারণত সাড়া বা রেসপন্সের অপেক্ষায় ব্লক হয়ে থাকে। শত শত সমসাময়িক ইউজারদের ক্ষেত্রে এটি গুণ করলে, কলিং সার্ভিসের উপলব্ধ সকেট পুল কয়েক সেকেন্ডের মধ্যে শেষ হয়ে যায়। ফলে কলারটি ক্র্যাশ করে, যা ট্রাফিককে অন্য নোডগুলোতে রিডাইরেক্ট করে এবং পুরো ইনফ্রাস্ট্রাকচার জুড়ে একটি মারাত্মক ক্যাসকেডিং ফেইলর ট্রিগার করে।

## ডিফেন্সিভ ইঞ্জিনিয়ারিং: সার্কিট ব্রেকার এবং অ্যাডাপ্টিভ লোড শেডিং

ক্যাসকেডিং ফেইলর নিষ্ক্রিয় করার জন্য সিস্টেমগুলোকে প্রঅ্যাক্টিভ আইসোলেশন বাউন্ডারি বাস্তবায়ন করতে হবে। প্রচণ্ড চাপের মুখে ক্লাস্টার ব্যালেন্স বজায় রাখার দুটি অপরিহার্য প্যাটার্ন হলো **সার্কিট ব্রেকার (Circuit Breaker)** এবং **অ্যাডাপ্টিভ লোড শেডিং (Adaptive Load Shedding)**।

```
                ┌──────────────────────────────────────────────┐
                │                                              │
                ▼                                              │ Success Threshold
        ┌──────────────┐          Failures > Limit      ┌─────────────┐ Met
        │              │───────────────────────────────>│             │
        │    CLOSED    │                                │    OPEN     │
        │ (Normal Ops) │<───────────────────────────────│ (Fast Fail) │
        └──────────────┘           Reset Timeout        └─────────────┘
                ▲                     Expired                  │
                │                                              │
                │              ┌────────────────┐              │
                └──────────────│   HALF-OPEN    │<─────────────┘
                 Success >= N  │ (Probe Traffic)│
                               └────────────────┘
```

### সার্কিট ব্রেকার প্যাটার্ন

একটি সার্কিট ব্রেকার সংবেদনশীল আউটবাউন্ড নেটওয়ার্ক ইনভোকেশনকে র‍্যাপ করে এবং স্লাইডিং টাইম উইন্ডোতে হিস্টোরিকাল ফেইলর রেট ট্র্যাক করে। স্টেট মেশিনটি তিনটি মৌলিক ফেজের মধ্য দিয়ে পরিবর্তিত হয়:

- **Closed:** রিকোয়েস্টগুলো নির্বিঘ্নে অতিক্রম করে। যদি পর পর ফেইলর রেট নির্দিষ্ট থ্রেশহোল্ড অতিক্রম করে (যেমন, ১০ সেকেন্ডে ৫০% এরর), তবে ব্রেকারটি ট্রিপ করে।
- **Open:** নেটওয়ার্ক I/O-এর কোনো চেষ্টা না করেই ইনবাউন্ড ইনভোকেশনগুলো তাত্ক্ষণিকভাবে ব্যর্থ হয়। কলার এক মিলিসেকেন্ডেরও কম সময়ে একটি নির্দিষ্ট ফলব্যাক রেসপন্স বা লোকাল এরর পায়।
- **Half-Open:** একটি পূর্বনির্ধারিত কুলডাউন সময়ের পর, ক্যানারি প্রোব ট্রাফিকের একটি অত্যন্ত সামান্য অংশ অতিক্রম করার অনুমতি পায়। যদি প্রোবগুলো সফল হয়, তবে ব্রেকারটি Closed স্টেটে ফিরে আসে; কোনো প্রোব ব্যর্থ হলে, এটি Open টাইমার রিসেট করে।

এখানে স্লাইডিং-উইন্ডো সার্কিট ব্রেকার উইথ ব্যাকঅফ কুলডাউন প্রদর্শনকারী একটি প্রোডাকশন-গ্রেড TypeScript ইমপ্লিমেন্টেশন দেওয়া হলো:

```typescript
type CircuitState = "CLOSED" | "OPEN" | "HALF_OPEN";

interface CircuitBreakerOptions {
  failureThreshold: number; // e.g. 5 failures
  recoveryTimeMs: number;   // e.g. 10000ms
  halfOpenMaxCalls: number; // e.g. 3 probe attempts
}

export class CircuitBreaker {
  private state: CircuitState = "CLOSED";
  private failureCount = 0;
  private halfOpenSuccesses = 0;
  private nextAttempt = Date.now();

  constructor(
    private readonly name: string,
    private readonly options: CircuitBreakerOptions
  ) {}

  public async execute<T>(action: () => Promise<T>): Promise<T> {
    if (this.state === "OPEN") {
      if (Date.now() > this.nextAttempt) {
        this.state = "HALF_OPEN";
        this.halfOpenSuccesses = 0;
      } else {
        throw new Error(`[CircuitBreaker: ${this.name}] Breaker is OPEN. Execution short-circuited.`);
      }
    }

    try {
      const result = await action();
      this.onSuccess();
      return result;
    } catch (error) {
      this.onFailure();
      throw error;
    }
  }

  private onSuccess(): void {
    if (this.state === "HALF_OPEN") {
      this.halfOpenSuccesses++;
      if (this.halfOpenSuccesses >= this.options.halfOpenMaxCalls) {
        this.state = "CLOSED";
        this.failureCount = 0;
      }
    } else {
      this.failureCount = 0;
    }
  }

  private onFailure(): void {
    this.failureCount++;
    if (this.state === "HALF_OPEN" || this.failureCount >= this.options.failureThreshold) {
      this.state = "OPEN";
      this.nextAttempt = Date.now() + this.options.recoveryTimeMs;
    }
  }
}
```

<Callout type="tip">
**Production Tip:** সার্কিট ব্রেকারগুলোকে Exponential Backoff এবং Decorrelated Jitter-এর সাথে যুক্ত করুন। ব্যর্থ অপারেশনগুলো পুনরায় চেষ্টা (retry) করার সময়, সাধারণ নির্দিষ্ট সময়ের ব্যবধানগুলো ক্লায়েন্টের রিট্রাই ওয়েভকে সিঙ্ক্রোনাইজ করে, যা ইতিমধ্যেই বিপর্যস্ত ব্যাকএন্ড ডেটাবেসের বিরুদ্ধে কৃত্রিম ডিস্ট্রিবিউটেড ডিনায়েল অফ সার্ভিস (DDoS) স্পাইক তৈরি করে।
</Callout>

### অ্যাডাপ্টিভ লোড শেডিং উইথ ব্যাকপ্রেসার

যখন কোনো ডাউনস্ট্রিম ডেটাবেস বা কম্পিউটেশনাল ইঞ্জিন স্যাচুরেশনের কাছাকাছি পৌঁছায়, তখন স্ট্যান্ডার্ড কিউইং আর্কিটেকচারগুলো ইনকামিং রিকোয়েস্টগুলোকে মেমোরিতে বাফার করে। কিউতে থাকা রিকোয়েস্টগুলো অপেক্ষারত থাকায়, ক্লায়েন্ট HTTP ক্লায়েন্টগুলোর টাইমআউট হয়ে যায় এবং তারা কানেকশন ছেড়ে দেয়।

যাইহোক, সার্ভারটি কয়েক মিনিট পরেও পরিত্যাগ করা রিকোয়েস্ট প্রসেস করা চালিয়ে যায়, এমন কাজে CPU সাইকেল নষ্ট করে যার ফলাফল ক্লায়েন্ট সাথে সাথে ফেলে দেবে।

অ্যাডাপ্টিভ লোড শেডিং এই প্যারাডাইম পরিবর্তন করে:

- সার্ভিসগুলো অভ্যন্তরীণ কিউ ল্যাটেন্সি, CPU স্যাচুরেশন এবং গার্বেজ কালেকশন ফ্রিকোয়েন্সি মনিটর করে।
- প্রসেসিং ল্যাটেন্সি সর্বোচ্চ গ্রহণযোগ্য SLA অতিক্রম করার সাথে সাথেই, HTTP 429 বা 503 ব্যবহার করে API গেটওয়ে লেয়ারে নতুন কম-প্রাধান্যযুক্ত রিকোয়েস্টগুলো প্রঅ্যাক্টিভলি প্রত্যাখ্যান করা হয়।
- প্রায়োরিটি কিউইং নিশ্চিত করে যে সংকটপূর্ণ হেলথ চেক, ট্রানজেকশন কমিট এবং অথেন্টিকেটেড ইউজার মিউটেশনগুলো শেডিং ফিল্টারকে বাইপাস করে, অন্যদিকে ব্যাকগ্রাউন্ড ওয়েবহুক এবং অ্যানালিটিক্স স্ট্রিম বিলম্বিত হয়।
