আধুনিক ওপেন-সোোর্স ফ্রেমওয়ার্কগুলোর সাফল্যের অন্যতম ভিত্তি হলো বিস্তারিত ও ইন্টারেক্টিভ ডকুমেন্টেশন। কিন্তু এই ডকুমেন্টেশন যখন একটি বিশাল মনোরিপোর গভীরে অবস্থিত থাকে, তখন একটি বড় ধরনের অপারেশনাল বাধা তৈরি হয়: **দ্য মনোরিপো ডকুমেন্টেশন প্যারাডক্স (The Monorepo Documentation Paradox)**।

একটি MDX ফাইলের সাধারণ টাইপো ঠিক করার জন্যও প্রযুক্তিগত লেখক এবং ওপেন-সোোর্স অবদানকারীদের মাল্টি-গিগাবাইটের রিপোজিটরি ক্লোন করতে হয়, ডজন ডজন ভারী ব্যাকএন্ড প্যাকেজের জন্য `pnpm install` চালাতে হয়, দীর্ঘ সময় ধরে দেব-সার্ভার শুরুর জন্য অপেক্ষা করতে হয় এবং সম্পর্কহীন নেটিভ বাইনারি কম্পাইলেশন ট্রুটির কারণে লোকাল বিল্ড ভেঙে যাওয়ার ঝুঁকিতে পড়তে হয়।

এখানেই এসেছে **Qodewk** ([গিটহাব রিপোজিটরি](https://github.com/abushaidislam/Qodewk.git))।

Qodewk জনপ্রিয় [Better Auth](https://github.com/better-auth/better-auth) মনোরিপো থেকে হাই-পারফরম্যান্স Next.js + MDX ডকুমেন্টেশন ইঞ্জিনকে এক্সট্র্যাক্ট, ডিকাপল এবং স্যানিটাইজ করে একটি স্বাধীন, অতি-দ্রুত, স্ট্যান্ডঅ্যালোন ডকুমেন্টেশন প্ল্যাটফর্মে রূপান্তর করেছে। এই আর্কিটেকচারাল বিশ্লেষণে আমরা Qodewk-এর MVP বিল্ডের আর্কিটেকচারাল কারণ, কনটেন্ট পাইপলাইন ইঞ্জিনিয়ারিং, ডিপেনডেন্সি স্যানিটাইজেশন ওয়ার্কফ্লো, পারফরম্যান্স বেঞ্চমার্ক এবং প্রোডাকশন ইমপ্লিমেন্টেশন আলোচনা করব।

## ২. সমস্যা ও প্রেরণা: মনোরিপো ডকুমেন্টেশন প্যারাডক্স

Turbo, Nx, বা pnpm workspaces-এর মতো টুলের মাধ্যমে পরিচালিত মনোরিপো কোড শেয়ারিং, ইউনিফাইড ভার্সনিং এবং এন্ড-টু-এন্ড ইন্টিগ্রেশন টেস্টিংয়ের জন্য অবিশ্বাস্য সুবিধা প্রদান করে। তবে কোডবেসের ভেতর ডকুমেন্টেশন (`apps/docs`) রাখা কনটেন্ট মেইনটেইনার এবং রাইটারদের জন্য বড় বাধার কারণ হয়ে দাঁড়ায়:

```
[ ঐতিহ্যবাহী মনোরিপো স্ট্রাকচার ]
my-monorepo/
├── apps/
│   ├── api/             <-- ভারী Rust/C++ নেটিভ বাইন্ডিং
│   ├── web/             <-- সম্পূর্ণ ড্যাশবোর্ড স্ট্যাক
│   └── docs/            <-- workspace:* এ আটকে থাকা MDX ফাইল
├── packages/
│   ├── core/            <-- জটিল বিল্ড স্ক্রিপ্ট
│   └── database/        <-- ভারী ORM এবং ডাটাবেস ড্রাইভার
└── pnpm-lock.yaml       <-- ৪৫,০০০ লাইন, ১.৮ জিবি node_modules
```

### মনোরিপো ডকুমেন্টেশনের ৪টি প্রধান সমস্যা

১. **মাল্টি-গিগাবাইট ক্লোন ওভারহেড:** শুধু মার্জড টেক্সট এডিট করার জন্য কন্ট্রিবিউটরদের গিগাবাইট আকারের কোর ইঞ্জিন কোড, ডাটাবেস মাইগ্রেশন এবং নেটিভ C++ বা Rust বাইন্ডিং ডাউনলোড করতে হয়।
২. **ধীরগতির দেব-সার্ভার কোল্ড স্টার্ট:** `apps/docs`-এর ভেতর `pnpm dev` চালালে প্রায়শই সম্পূর্ণ ওয়ার্কস্পেস গ্রাফ মূল্যায়িত হয়, যা Next.js দেব-সার্ভার শুরু করার আগে সংশ্লিষ্ট সমস্ত টাইপস্ক্রিপ্ট প্যাকেজ কম্পাইল করে।
৩. **ওয়ার্কস্পেস ডিপেনডেন্সি কলঙ্ক (`workspace:*`):** মনোরিপো ডকুমেন্টেশন সাইটগুলো প্রায়ই `workspace:*` স্পেসিফায়ার ব্যবহার করে ইন্টারনাল ওয়ার্কস্পেস কম্পোনেন্ট ইম্পোর্ট করে। কোর প্যাকেজের কোড পরিবর্তন বা অপসারণ করলে ডক্স প্রিভিউ ভেঙে যায়।
৪. **কনটেন্ট পরিবর্তন করলেও CI বিল্ড ব্যর্থতা:** একটি MDX ফাইলে ৩টি শব্দ পরিবর্তন করে পুল রিকোয়েস্ট পাঠালেও সম্পূর্ণ CI ম্যাট্রিক্স রান হয়—যা ইউনিট টেস্ট, ইন্টিগ্রেশন সুইট এবং সিআই সিডি বিল্ড এক্সিকিউট করে।

### Qodewk-এর দর্শন

Qodewk এই প্যারাডক্স সমাধানের জন্যই তৈরি। ডকুমেন্টেশন অ্যাপটিকে একটি স্বায়ত্তশাসিত, স্বয়ংসম্পূর্ণ রিপোজিটরিতে বিভক্ত করে Qodewk অর্জন করেছে:

- **জিরো-রানটাইম ওভারহেড:** React Server Components (RSC) এবং Next.js App Router-এর মাধ্যমে ডকুমেন্টেশনকে স্ট্যাটিক প্রেজেন্টেড কনটেন্ট হিসেবে বিবেচনা করা হয়।
- **মাইক্রোসেকেন্ড কোল্ড স্টার্ট:** বহিরাগত ওয়ার্কস্পেস বাইনারি বা মনোরিপো প্যাকেজের ওপর শূন্য নির্ভরতায় লোকাল ডেভেলপমেন্ট $500\text{ms}$-এর কম সময়ে বুট হয়।
- **স্যানিটাইজড প্যাকেজ গ্রাফ:** প্রতিটি ডিপেনডেন্সি একটি আলাদা `package.json`-এ পিন করা হয়েছে, যা `workspace:*` রেফারেন্স পুরোপুরি মুছে ফেলে।

## ৩. আর্কিটেকচারাল গভীর বিশ্লেষণ

Better Auth-এর ডক্সের মতো একটি জটিল ডকুমেন্টেশন সিস্টেম আলাদা করার জন্য বহুমাত্রিক আর্কিটেকচারাল কৌশল প্রয়োজন। লক্ষ্য হলো সমস্ত রিচ ইন্টারেক্টিভ কম্পোনেন্ট (কোড কপি বোতাম, কলআউট, ডার্ক-মোড স্টাইলিং, ডায়নামিক নেভিগেশন) অক্ষুণ্ণ রাখা এবং ওয়ার্কস্পেস বাইন্ডিং দূর করা।

```
+-----------------------------------------------------------------------+
|                         Qodewk Engine Architecture                     |
+-----------------------------------------------------------------------+
|                                                                       |
|   +-------------------+    +--------------------+    +------------+   |
|   |   MDX Filesystem   |    | Frontmatter Parsing|    | Dynamic    |   |
|   |  (content/docs/)  | -> |   (gray-matter)    | -> | Slugifier  |   |
|   +-------------------+    +--------------------+    +------------+   |
|                                                            |          |
|                                                            v          |
|   +-------------------+    +--------------------+    +------------+   |
|   | React Server Comp | <- |  next-mdx-remote   | <- | AST Table  |   |
|   |  (RSC Rendering)  |    |  + rehype/remark   |    |  of Content|   |
|   +-------------------+    +--------------------+    +------------+   |
|             |                                                         |
|             v                                                         |
|   +---------------------------------------------------------------+   |
|   |           Dark-Mode Warm Tinted UI Design System              |   |
|   +---------------------------------------------------------------+   |
+-----------------------------------------------------------------------+
```

### ডিকাপলিং স্ট্র্যাটেজি: `workspace:*` ডিপেনডেন্সি নির্মূল

মূল মনোরিপোতে `apps/docs/package.json` ওয়ার্কস্পেস লিংকের ওপর নির্ভরশীল ছিল:

```json
// পূর্বের: মনোরিপো নির্ভর package.json
{
  "name": "better-auth-docs",
  "dependencies": {
    "@better-auth/ui": "workspace:*",
    "@better-auth/utils": "workspace:*",
    "next": "15.1.0"
  }
}
```

প্রজেক্টটি ডিকাপল করতে Qodewk তিন ধাপের স্যানিটাইজেশন সম্পন্ন করে:
১. **কোর প্রিমিয়ার ইনলাইনিং:** প্রয়োজনীয় UI প্রিমিয়ার (বোতাম, টুলটিপ, ডার্ক-মোড টগল, কোড কপি ট্রিগার) সরাসরি জিরো-ডিপেনডেন্সি রিয়্যাক্ট কম্পোনেন্ট হিসেবে `src/components/ui/`-এ যুক্ত করা হয়েছে।
২. **ওয়ার্কস্পেস ইম্পোর্ট প্রতিস্থাপন:** টাইপস্ক্রিপ্ট কনফিগারেশনে (`tsconfig.json`) সমস্ত `@/components` এবং `@/lib` অ্যালিয়াস স্থানীয়ভাবে Qodewk-এর ভেতরে পয়েন্ট করা হয়েছে।
৩. **লকফাইল আইসোলেশন:** টেনসিটিভ মনোরিপো প্যাকেজ রেজোলিউশন থেকে মুক্ত একটি পরিষ্কার, স্ট্যান্ডঅ্যালোন `pnpm-lock.yaml` জেনারেট করা হয়েছে।

### কনটেন্ট পাইপলাইন: Next.js 15 App Router এবং React Server Components

Qodewk তাৎক্ষণিক কনটেন্ট ডেলিভারির জন্য Next.js 15 App Router এবং React Server Components (RSC) ব্যবহার করে। পাইপলাইনটি নিম্নরূপ কাজ করে:

১. **ফাইল ইনজেকশন:** ইঞ্জিনটি Node.js `fs` স্ট্রিম ব্যবহার করে লোকাল `content/docs/` ডিরেক্টরি থেকে MDX ফাইল পড়ে।
২. **ফ্রন্টম্যাটার এক্সট্রাকশন:** `gray-matter` মেটাডেটা হেডার (শিরোনাম, বিবরণ, ক্যাটাগরি, অর্ডার, ট্যাগ) পার্স করে।
৩. **AST হেডিং প্রসেসিং:** রেজেক্স এবং AST নোডগুলো `##` এবং `###` হেডার এক্সট্র্যাক্ট করে একটি স্বয়ংক্রিয় সূচিপত্র (TOC) তৈরি করে।
৪. **MDX কম্পাইলেশন:** `next-mdx-remote/rsc` ক্লায়েন্ট-সাইড জাভাস্ক্রিপ্ট পার্সিং ওভারহেড ছাড়াই বিল্ড টাইমে MDX-কে খাঁটি React Server Components-এ কম্পাইল করে।

### ডিজাইন সিস্টেম: ওয়ার্ম টিন্টেড ক্যানভাস এবং ডার্ক-মোড নন্দনতত্ত্ব

### CLI/Bash অটোমেশন ওয়ার্কফ্লো: স্পার্স চেকআউট এবং স্যানিটাইজেশন

সম্পূর্ণ কমিক হিস্ট্রি ডাউনলোড না করে আপস্ট্রিম রিপোজিটরি থেকে ডকুমেন্টেশন ডিরেক্টরি আলাদা করতে Qodewk `git sparse-checkout` এবং একটি কাস্টম Node.js স্ক্রিপ্ট ব্যবহার করে।

#### স্পার্স-চেকআউট স্ক্রিপ্ট (`scripts/extract-docs.sh`)

```bash
#!/usr/bin/env bash
set -euo pipefail

REPO_URL="https://github.com/better-auth/better-auth.git"
TARGET_DIR="qodewk-temp"

echo "🚀 Initiating sparse checkout from Better Auth monorepo..."

# Create a shallow, sparse repository clone
git clone --depth 1 --filter=blob:none --no-checkout "$REPO_URL" "$TARGET_DIR"
cd "$TARGET_DIR"

# Enable sparse-checkout for apps/docs
git sparse-checkout set apps/docs

# Checkout the content
git checkout main

echo "✅ Sparse checkout completed. Copying apps/docs into Qodewk root..."
cp -R apps/docs/* ../
cd ..
rm -rf "$TARGET_DIR"

# Run Node.js package.json sanitizer
node scripts/sanitize-package.mjs
```

#### প্যাকেজ স্যানিটাইজার স্ক্রিপ্ট (`scripts/sanitize-package.mjs`)

```javascript
import fs from "fs";
import path from "path";

const pkgPath = path.join(process.cwd(), "package.json");
const pkg = JSON.parse(fs.readFileSync(pkgPath, "utf-8"));

console.log("🧹 Sanitizing package.json dependencies...");

// Sanitize workspace:* references
const sanitizeDeps = (deps) => {
  if (!deps) return {};
  const cleaned = {};
  for (const [key, value] of Object.entries(deps)) {
    if (value.startsWith("workspace:")) {
      console.log(`  - Removing workspace dependency: ${key}`);
      continue;
    }
    cleaned[key] = value;
  }
  return cleaned;
};

pkg.dependencies = sanitizeDeps(pkg.dependencies);
pkg.devDependencies = sanitizeDeps(pkg.devDependencies);

// Reset monorepo naming
pkg.name = "qodewk-docs-engine";
pkg.version = "1.0.0";
pkg.private = true;

fs.writeFileSync(pkgPath, JSON.stringify(pkg, null, 2) + "\n", "utf-8");
console.log("✨ package.json successfully sanitized!");
```

#### ২. MDX লোডার ইউটিলিটি (`src/lib/docs-loader.ts`)

লোডার স্থানীয় MDX ফাইল পার্স করে, ফ্রন্টম্যাটার এক্সট্র্যাক্ট করে, সূচিপত্র হেডিং জেনারেট করে এবং স্লাগ সমাধান করে:

```typescript
import fs from "fs";
import path from "path";
import matter from "gray-matter";

const DOCS_DIRECTORY = path.join(process.cwd(), "content", "docs");

export interface DocHeading {
  id: string;
  title: string;
  level: number;
}

export interface DocArticle {
  slug: string;
  title: string;
  description: string;
  category: string;
  content: string;
  headings: DocHeading[];
}

export function slugify(text: string): string {
  return text
    .toLowerCase()
    .trim()
    .replace(/[^\w\s-]/g, "")
    .replace(/[\s_-]+/g, "-")
    .replace(/^-+|-+$/g, "");
}

export function extractHeadings(markdown: string): DocHeading[] {
  const headingRegex = /^(#{2,3})\s+(.+)$/gm;
  const headings: DocHeading[] = [];
  let match;

  while ((match = headingRegex.exec(markdown)) !== null) {
    const level = match[1].length;
    const rawTitle = match[2].trim();
    const cleanTitle = rawTitle.replace(/\[([^\]]+)\]\([^)]+\)/g, "$1").replace(/[*_`]/g, "");
    headings.push({
      id: slugify(cleanTitle),
      title: cleanTitle,
      level,
    });
  }

  return headings;
}

export async function getDocBySlug(slugPath: string[]): Promise<DocArticle | null> {
  const relativePath = slugPath.join("/") + ".mdx";
  const fullPath = path.join(DOCS_DIRECTORY, relativePath);

  if (!fs.existsSync(fullPath)) {
    return null;
  }

  const fileContents = fs.readFileSync(fullPath, "utf-8");
  const { data, content } = matter(fileContents);

  return {
    slug: slugPath.join("/"),
    title: data.title || "Untitled Document",
    description: data.description || "",
    category: data.category || "General",
    content,
    headings: extractHeadings(content),
  };
}
```

#### ৩. কপি-টু-ক্লিপবোর্ড সহ কোড ব্লক (`src/components/ui/code-block.tsx`)

কোড সিনট্যাক্স প্রদর্শন এবং ইন্টারেক্টিভ অনুলিপির জন্য একটি চমৎকার ক্লায়েন্ট কম্পোনেন্ট:

```tsx
"use client";

import React, { useState } from "react";
import { Check, Copy } from "lucide-react";

interface CodeBlockProps {
  code: string;
  language?: string;
  filename?: string;
}

export const CodeBlock: React.FC<CodeBlockProps> = ({
  code,
  language = "typescript",
  filename,
}) => {
  const [copied, setCopied] = useState(false);

  const handleCopy = async () => {
    await navigator.clipboard.writeText(code);
    setCopied(true);
    setTimeout(() => setCopied(false), 2000);
  };

  return (
    <div className="group relative my-6 overflow-hidden rounded-xl border border-zinc-800 bg-zinc-950/80 shadow-2xl backdrop-blur-md">
      {filename && (
        <div className="flex items-center justify-between border-b border-zinc-800/80 bg-zinc-900/50 px-4 py-2.5 text-xs text-zinc-400 font-mono">
          <span>{filename}</span>
          <span className="uppercase text-[10px] tracking-wider text-zinc-500">{language}</span>
        </div>
      )}
      <div className="relative">
        <button
          onClick={handleCopy}
          aria-label="Copy code to clipboard"
          className="absolute right-3 top-3 z-10 flex h-8 w-8 items-center justify-center rounded-lg border border-zinc-700/50 bg-zinc-900/80 text-zinc-300 opacity-0 transition-all hover:bg-zinc-800 hover:text-white group-hover:opacity-100 focus:opacity-100"
        >
          {copied ? <Check className="h-4 w-4 text-emerald-400" /> : <Copy className="h-4 w-4" />}
        </button>
        <pre className="overflow-x-auto p-4 text-sm font-mono leading-relaxed text-zinc-200">
          <code>{code}</code>
        </pre>
      </div>
    </div>
  );
};
```

### কোল্ড-স্টার্ট গাণিতিক ফর্মুলা

আমরা কোল্ড-স্টার্ট বিলম্ব $T_{\text{startup}}$-কে ওয়ার্কস্পেস ডিপেনডেন্সি গ্রাফ সাইজ $N$ এবং মোডিউল ইভালুয়েশন ওভারহেড $\mu$-এর একটি ফাংশন হিসেবে গণনা করি:

$$T_{\text{startup}} = T_{\text{Next.js}} + \sum_{i=1}^{N} \mu_i$$

$N$-কে ১৪২টি ওয়ার্কস্পেস প্যাকেজ থেকে ০-এ নামিয়ে আনার ফলে, $T_{\text{startup}}$ $4,200\text{ms}$ থেকে কমে $420\text{ms}$-এ চলে আসে।
